1맵 마을 수호 석상 — Tripo → Mixamo 전달 패키지
2026-11-10 / 최종 본체 포즈: T-POSE

가장 먼저
노멀: 01_Normal/front.png
하드: 02_Hard/front.png
각각 독립된 모델로 생성한다. 본체에 돌봉·방패·날개를 합쳐 생성하지 않는다.
9장의 입력 이미지가 있지만 생성할 기본 모델 종류는 본체 2개와 소품 3개, 총 5개다.

폴더와 업로드 단위
01_Normal/
  front.png : 무기 없는 노멀 T포즈 정면, 기본 단일 입력
  left.png  : 같은 T포즈의 측면, 캐릭터가 화면 오른쪽을 보는 모습
  back.png  : 같은 T포즈 후면
02_Hard/
  front.png : 날개/무기 없는 하드 가고일 T포즈 정면, 기본 단일 입력
  left.png  : 같은 T포즈의 측면, 캐릭터가 화면 오른쪽을 보는 모습
  back.png  : 같은 T포즈 후면, 날개 부착 위치 참고
03_Club/input.png : 돌봉 1개
04_Shield/input.png : 방패 1개
05_Wing/input.png : 하드 날개 한쪽 모듈 1개
ReferenceOnly/ : 기존 승인 컨셉 시트 2장. 검토용이며 직접 업로드하지 않는다.
GenerationPrompts/ : 이번 이미지 생성/편집에 사용한 원문. Tripo Image-to-3D 입력란에 붙이는 텍스트가 아니다.

중요한 시점/포즈 설명
- 본체 모두 수평으로 팔을 편 T포즈, 열린 빈손, 곧은 다리다.
- 정면에서 본 팔과 측면에서 겹쳐 보이는 팔은 같은 자세다. 측면에서 짧게 보이는 팔을 아래로 내려 재포즈하지 않는다.
- 좌표를 Y위/+Z정면/+X캐릭터오른쪽으로 잡으면, 인물이 화면 오른쪽을 보는 측면은 카메라가 캐릭터 왼쪽(-X)에 있는 뷰다. 파일명을 left.png로 정리했다.
- 이미지 생성 요청문에는 right side라는 표현이 있었으나, 실제 화면 방향을 기준으로 최종 파일명과 매니페스트를 바로잡았다.
- 생성된 시점들은 같은 설계를 맞춘 참조이지 실제 단일 3D 모델에서 렌더한 측량 정투영은 아니다. 미세한 투영/장식 차이가 결과를 방해하면 front.png만으로 시작하고 Tripo 내부 다중시점 생성으로 보완한다.
- normal과 hard는 별도 이미지 세트다. 서로 다른 몸체를 한 모델의 다중시점으로 섞지 않는다.

Tripo 사용 순서
1. ZIP을 풀고, 먼저 01_Normal/front.png를 Image-to-3D에 넣는다.
2. 앞뒤/두께 정보가 필요하면 같은 01_Normal의 front/left/back을 Multi-view에 넣는다. 기존 ReferenceOnly 시트를 그 슬롯에 넣지 않는다.
3. 02_Hard도 별도 생성 작업으로 같은 방식으로 처리한다. 하드 본체에는 날개가 없다.
4. 03_Club, 04_Shield, 05_Wing은 각 input.png를 별도 생성한다. 이 세 파일을 본체 다중시점 슬롯에 함께 넣으면 안 된다.
5. 본체 생성 단계에서는 Mixamo를 쓸 예정이므로 Tripo에서 별도 리그/애니메이션을 붙일 필요가 없다.
6. 내보내기는 Mixamo가 받는 FBX를 우선한다. OBJ를 쓸 경우 MTL과 텍스처를 함께 보관한다. GLB 파일을 그대로 Mixamo에 올리지 않는다.
7. Tripo 결과의 어깨/팔꿈치/손가락, 가랑이/무릎/발목, 목과 몸 연결을 확인한다. 무릎 뒤 석판이나 손가락이 붙어 버리면 리깅 전에 분리/형태 정리가 필요하다.
8. 파일에 떠 있는 갑옷 조각이나 바닥이 생겼으면 제거하거나 본체와 올바르게 연결한다. 원점과 정면을 정렬한다.
9. 날개 모듈은 Tripo가 힌지를 움직이는 별도 부품/본으로 자동 분리해 준다고 가정하지 않는다. 하나의 조형으로 생성된 뒤 DCC에서 분할할 작업이 남을 수 있다.

Mixamo 사용 순서
1. 무기/방패/날개가 없는 노멀 또는 하드 본체 FBX를 올린다.
2. 손목/팔꿈치/무릎/가랑이 등의 마커를 실제 관절에 놓고 리깅한다. 돌출된 견갑 장식 끝을 어깨 관절로 보지 않는다.
3. 하드의 큰 손/발과 짧은 비례 때문에 자동 결과는 실제로 확인해야 한다. T포즈가 성공을 보장하지는 않는다.
4. 먼저 걷기/대기/팔 들기/무릎 굽힘 등으로 손가락, 견갑, 석재 치마판의 변형을 확인한다.
5. 리깅된 본체를 내려받은 뒤 장비와 날개를 붙인다. 이 패키지의 PNG를 Mixamo에 직접 업로드하는 것이 아니다.

장비/날개 조립
- 노멀 돌봉: 오른손 소켓에 별도 메시로 연결한다. 돌봉 손잡이 중앙을 소품 피벗으로 정리한다.
- 노멀 방패: 왼손/전완 브레이스에 별도 메시로 연결한다. 뒷면 손잡이는 전면 입력에서 보이지 않으므로 생성 결과에서 확인하고 필요하면 수동 제작한다.
- 하드 본체는 돌봉/방패를 들지 않는다. 성문 부조는 전완 장갑에 이미 들어 있다.
- 날개는 한쪽 모듈을 생성한 뒤, DCC에서 복제·좌우 미러하고 면 방향/스케일을 적용해 다른 쪽을 만든다.
- 날개 루트는 상부 척추/등 보강판에 부착한다. 상완/견갑의 팔 본에 붙이지 않는다.
- 날개를 접고 펼치려면 좌우 각각 root/upper와 tip에 해당하는 최소 2개 관절을 별도로 잡고, 단단한 석판은 각 관절에 강체처럼 가중치를 준다.
- Mixamo 이족 휴머노이드 리그가 날개 본이나 비행 애니메이션을 자동으로 만들어 준다고 기대하지 않는다.
- 간단히 고정된 날개만 필요하면 등 소켓에 강체로 붙이는 방식도 가능하다. 움직이는 날개는 별도 본/애니메이션 작업이다.

규모/재질 참고 — 확정값 아님
노멀 본체 약4m, 하드 약5.2m는 이전 설계의 출발점이다. Tripo가 이 실측 크기를 자동 보장하지 않는다.
게임의 기존 타격 반경과 외형 크기는 따로 관리한다.
아이보리 석재·남색·연금색·연보라 그림자를 유지한다. 하반신에는 태엽 노출을 추가하지 않는다.
날개를 포함한 최종 비례는 ReferenceOnly/hard-concept-do-not-upload.png를 따른다.

이번 전달물의 범위
- 실제 업로드용 단일 대상 PNG 9장, 기존 컨셉 참고 2장, 안내/생성 프롬프트/매니페스트.
- 도중 만든 A포즈 이미지는 최종 패키지에 넣지 않았다.
- Tripo 업로드·3D 생성·크레딧 사용·Mixamo 리깅은 실행하지 않았다. FBX/OBJ/GLB 모델은 아직 없다.
- 원본 컨셉·게임 코드·씬·프리팹은 수정하지 않았다.

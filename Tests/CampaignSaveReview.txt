실제 2부 생성/참가 버튼을 사용할 수 있게 하는 단계는 완료되지 않았다. 콘텐츠·8인 지원·
출발 선택 정책이 마련된 뒤 카탈로그/입장 검증/경계 검증을 연결해야 한다.
이는 가장 큰 미완료 사항이며, 현재 3스테이지 저장·이어하기에는 영향을 주지 않는다.

4. 저장 형식과 계정 분리

Application.persistentDataPath/campaign/<owner>/
  progress.json       개인의 호스트 확정 클리어와 챕터 해금
  checkpoint.json     호스트/싱글의 마지막 안전 경계
  각 파일의 .bak     최근 정상 백업

owner는 인증된 steam-<SteamID64> 또는 offline-local.
설정 파일과 분리하며 Assets/설치 폴더에 쓰지 않는다. Steam 계정 간 및 오프라인 간
자동 이전/합산은 하지 않는다. 메뉴에서 계정이 바뀌면 해당 계정 파일을 다시 읽고,
실행 중 계정 변경은 해당 세션 저장을 중단하고 안내한다.
같은 OS 사용자 안의 오프라인 저장은 하나이며 오프라인 다중 프로필은 없다.

checkpoint 주요 항목:
- schema version=1, content revision=prototype-3-roster12-v1
- GUID 런 ID와 GUID 영구 파티 슬롯 ID, 챕터/난이도/다음 스테이지/UTC 저장 시각
- 원래 인증 사용자 ID, 이름, 역할, 직업 고유 ID, 기원·R/F/V 고유 ID
- 카드 고유 ID와 중첩, 캐릭터 자원/스킬 상태, 경계 HP·포션 상태, Iris 코인
- 경계까지의 재도전 횟수·플레이 시간·클리어/실패 미터기 기록
- 처리한 런/챕터/스테이지 키와 선택 보상 키, 확정 카드 후보/선택 결과
- 카드 추첨용 seed와 현재 PRNG state
- 아직 원래 원격 참가자에게 전달하지 못한 호스트 확정 클리어 이벤트 outbox

표시 이름은 UI용이며 식별에 쓰지 않는다. 예: card.swift, job.aegis-paladin.
네트워크 actor ID와 GetInstanceID는 디스크 미터기에서도 GUID 슬롯으로 바꾼다.
오브젝트 참조·로비/연결 ID·전투 위치·패턴 진행·효과 코루틴은 저장하지 않는다.
캐릭터 스냅샷의 castTarget은 경계에서 0이어야 하며 임의 ID가 있으면 거부한다.

5. 정확한 저장/복원 시점과 상태 정책

A. 새 런의 직업·기원/파티 확정 -> 기존 PrepareEncounter로 Stage 1 시작 상태 준비
   -> 임시 효과 정리와 기존 초기화 완료 -> 최초 체크포인트 -> 로딩/카운트다운.
B. 호스트가 보스 클리어 확정 -> 개인 클리어 즉시 별도 저장/원격 전달
   -> 기존 카드 보상과 R/F/V 선택 모두 완료 -> 다음 스테이지 PrepareEncounter
   -> 다음 스테이지 시작 상태 체크포인트 -> 카운트다운.
C. 최종 클리어 -> 필요한 최종 스킬 선택 완료 -> completed=true 저장.
   메뉴에는 완료된 런으로 표시하고 이어하기를 비활성화.
D. 전투·재도전 도중에는 마지막 안전 경계를 덮어쓰지 않음.
   재실행 시 해당 스테이지 시작부터 재도전. 경계 이후 진행/재도전 기록은 롤백됨.

기존 경계 정책을 그대로 따른다:
- HP 최대, 보호막/지연 피해/변신/장판/소환물/연결/시전/콤보/임시 버프 정리
- 쿨타임 0, 충전 최대, X 포션 쿨타임 0 (포션 재고는 기존 무제한)
- Iris 코인 3으로 재설정
- 직업 자원은 각 resource.resetOnStage/initial 정책 사용. 유지형 자원은 정확히 복구.
- 직업/기원/카드/R/F/V 및 확정 보상 원장은 유지.

복원은 기본 역할 스탯 -> 저장 카드 수치 -> 직업 상태/기원 계산 -> 기존 전장 준비
-> 유지해야 할 저장 자원 재적용 순서다. 카드 획득 팝업/함성 펄스/보상 콜백은 재실행하지 않는다.
복원 진입에는 전용 TryResume(Loading)만 추가했으며 기존 로딩/카운트다운/플레이를 재사용한다.

개인 진행은 클리어 당시 살아 있는지와 무관하게 연결되고 제어권이 있는 실제 참가자에게만
확정한다. AI가 대신 조작하는 부재 사용자는 개인 클리어를 받지 않는다.
호스트의 클리어 기록을 다른 참가자에게 복사하지 않는다. 클라이언트는 자신의 인증 ID에
발급된 이벤트만 받으며 실제 개인 파일 저장 후 ACK한다. 중복 전달은 Record에서 거부한다.
체크포인트를 읽었다는 이유로 호스트의 과거 클리어/보상을 재실행하지 않는다.
outbox는 과거 보상 재생용 이력이 아니라 아직 ACK되지 않은 원격 이벤트 전달용이다.
마지막 경계 이후 ACK는 다음 안전 경계에 반영하므로 크래시 시 재전송될 수 있고,
클라이언트 개인 원장이 같은 클리어 키를 다시 지급하지 않는다.

6. 이어하기 사용 방법

싱글:
메인 메뉴 [새 게임 · 싱글플레이 / AI] -> 직업/기원 선택 -> 출발.
정상 보스 클리어와 카드/스킬 선택을 마치면 다음 스테이지 시작을 자동 저장한다.
메뉴로 돌아가거나 앱을 다시 켠 뒤 [이어하기]로 저장한 빌드·AI·스테이지를 복원한다.

Steam:
저장한 호스트가 같은 Steam 계정으로 [이어하기] -> 새 친구 로비 생성.
원래 참가자가 새 로비 초대를 수락 -> Steam 인증 ID로 자신의 기존 슬롯 복원.
이전 로비 연결 정보나 네트워크 ID는 사용하지 않는다.
직업/기원/카드/RFV는 고정. 복구 중인 사람은 상태 동기화를 끝내고 준비해야 한다.
부재 원래 참가자는 기존 AI가 같은 빌드로 유지하며 다른 신규 사용자에게 양도하지 않는다.
대기실 예약은 만료하지 않으며 출발 후에는 기존 60초 복귀 정책을 재사용한다.
실제 참가자 준비 -> 호스트 출발 -> 로딩 확인 -> 카운트다운.

[저장 정보 확인]: 챕터/난이도/다음 스테이지/시간/내 직업·루트/원래 파티 표시.
[개인 진행도 / 챕터 해금]: 개인 확정 기록과 1부/2부 조건 및 현재 콘텐츠 제한 표시.
[런 체크포인트 삭제]와 [개인 진행도 삭제]는 서로 별개의 확인 창을 사용한다.
각 삭제는 현재 계정의 선택한 파일과 백업만 지우며 설정과 키 배치는 유지한다.
Steam 로비 생성/접속 도중에는 삭제를 막는다. 원격 미전달 확정 이벤트가 남은 경우
개인 기록을 지운 뒤에도 그 이벤트가 실제 호스트에게서 도착할 수 있음을 UI에 명시했다.

7. 저장 실패/손상/호환성 정책

- 동일 디렉터리 임시 파일 -> Flush(true) -> File.Replace/첫 File.Move.
- 정상 이전 파일을 .bak로 보관. 손상된 원본 복구 중에는 정상 .bak를 보존.
- 읽기 실패/손상/미지원 버전은 게임 시작을 막지 않으며 이유를 표시.
- 미래 버전 원본이나 백업을 임의로 덮어쓰지 않음. 임의 기본값 저장도 하지 않음.
- 이전 캠페인 저장 형식은 존재하지 않아 v1만 지원. v0/기타 버전의 암묵적 이전 없음.
- 잘못된 직업/기원/스킬/카드, 선행 해금, 중복 원장, 누락된 선택, 비유한 자원,
  전투 중 상태, 역할/슬롯 불일치는 거부.
- 실패 시 게임 진행은 계속. 이전 정상 저장을 유지하고 실패 안내/HUD와 재시도 제공.
- 10초마다 또는 [저장 재시도]로 마지막 실패한 안전 경계 사본만 다시 기록.
  현재 전투 상태를 캡처해서 덮어쓰지 않는다. 새 안전 경계에 도달하면 최신 경계를 보관.
- 종료/메뉴/다른 방 이동 시 마지막 저장과 미저장 전투·선택을 안내하고 확인한다.
  Steam 클라이언트는 자신의 이전 호스트 저장 대신 현재 호스트가 복제한 저장
  스테이지/시각/완료/실패 상태를 사용한다. 연결이 끊긴 경우 마지막 수신 정보임을 표시한다.
- 강제 종료/전원 차단/Unity Play 중단에는 확인 창을 보장할 수 없으며, 이미 정상 저장된
  마지막 경계만 복원한다. 디스크 장애가 계속되는 동안 종료하면 실패한 경계는 유실된다.
- LAN 테스트는 인증된 영구 사용자 ID가 없어 진행도/런 저장 제외, UI에 안내.

우선순위 1: 싱글 경계/재실행
1) Console 재컴파일 확인 -> 메인 메뉴 저장 버튼/훈련장/기존 입력·키 배치 확인.
2) 개발 도구를 사용하지 않은 새 런으로 직업/기원 선택 -> Stage 1 출발 저장 표시.
3) 정상 Stage 1 클리어 -> 기존 카드와 R 선택 완료 -> Stage 2 저장 표시.
4) Stage 2에서 피해/자원 소모/포션/대쉬 사용 -> 메뉴 종료 확인 -> 앱 종료/재실행.
5) 이어하기: 같은 직업/기원/R/카드, Stage 2 시작, HP/포션/쿨타임/충전 정상화 확인.
6) Stage 2 클리어 후 카드/F, Stage 3 최종 V 선택 -> 완료 표시/이어하기 비활성 확인.
7) 현 prototype 3스테이지를 완료해도 1부 완료/2부 해금이 생기지 않는지 확인.

우선순위 2: 반복·오류·제외
8) 이어하기/새 게임/훈련장 반복 후 카드 효과/이벤트/파티/보스 잔류와 키 배치 확인.
9) 훈련장과 개발용 자원·카드·보스 처치를 사용한 런의 개인 기록/체크포인트 제외.
10) 테스트용 저장 사본으로 파일 잠금/손상/미래 version/누락 필드/백업 복구 확인.

우선순위 3: Steam 실제 두 계정 이상
12) 같은 protocol 12 빌드로 호스트/게스트 정상 보상 완료 후 호스트 저장 -> 모두 종료.

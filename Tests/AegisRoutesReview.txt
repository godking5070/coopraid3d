- 두 Steam 계정 또는 기존 다중 플레이어 실행/원본에서 만든 테스트 빌드로 호스트와 클라이언트를 실행. 모두 프로토콜 8 빌드 사용. 루트 선택 승인이 두 화면에 일치하고 변경 시 준비가 해제되는지 확인.
- 클라이언트가 팔라딘일 때 각각의 Z를 사용하여 비용/피해/보호막/가드/쿨타임/미터기가 한 번만 적용되는지 확인. 호스트 팔라딘도 별도 확인.
- 변신/가드/보호막/지연 피해 중 클라이언트 연결을 끊고 AI가 이어서 행동하는지, 60초 안에 같은 계정으로 복귀해 현재 남은 상태를 받는지 확인. 복귀로 재발동/치유/성광 환급이 없는지 확인.
- 재도전/보상/다음 스테이지 중 복귀, 메뉴/호스트 종료 후 다시 접속을 확인. 모든 플레이어의 카메라/키 설정은 로컬로 유지되어야 한다.

7. 다음 R/F 작업의 연결점
- stable slot: CharacterSlot.Active / OffGcd2. CharacterDefinition.unlocks에 afterStage/choices를 정의하고 기존 호스트 CharacterActor.Choose 및 공통 스킬 실행기를 사용.
- 패시브 보정은 공통 ShieldAmount/실행 컨텍스트, 반응 피해는 CombatHitContext/CombatDamageKind/CombatSecondaryDamage로 분류. 새 추가타가 Sun/Reflection으로 재귀하지 않도록 유지.
- 스킬별 쿨타임 감소에는 stable skill ID 사용. 루트 공용 정의에 사용자별 값을 저장하지 않음.
- 지속 상태를 추가하면 AegisStateSnapshot과 유효성 검사/스냅샷 복원/사망·재도전 정책/복귀 테스트를 함께 확장.
- 실제 카운터 가능한 보스 패턴은 기존 CombatCounterTarget.OpenWindow와 직접 피해 분류를 명시적으로 연결. 이번 작업에서는 패턴을 추가하지 않음.

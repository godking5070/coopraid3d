# 아스텔라 전투 코드 최적화 기록

2026년 11월 6일 실제 프로젝트 `C:\Astella\Astella`의 반복 메모리 할당과 UI 탐색 비용을 줄였다. 이번 변경은 코드 수준의 최적화이며, 실제 Unity 프레임 시간과 FPS는 측정하지 않았다.

## 변경 사항

| 경로 | 기존 비용 | 변경 |
| --- | --- | --- |
| 캐릭터 시전 상태 확인 | 매 프레임 스킬·자원·선택·효과 배열을 포함한 전체 상태 복사 | 시전 기술 ID·남은 시간·대상 ID만 읽음 |
| 팔라딘과 탱커·힐러·딜러 핵심 특성 확인 | 핵심 특성 문자열 하나를 읽으면서 전체 상태 복사 | 런타임 상태의 읽기 전용 문자열 조회 |
| 적 목록 갱신 | 매 프레임 새 적 목록 리스트와 배열 생성 | 컴포넌트가 가진 리스트를 비우고 재사용, 용량 증가 시에는 추가 할당 가능 |
| 직업 선택창 설정 UI 정렬 | 매 프레임 설정 UI 컴포넌트를 씬 전체에서 탐색 | 찾은 컴포넌트를 보관하고 소멸 시 다시 탐색, 기존 정렬 호출 유지 |

`CharacterRuntimeState.Snapshot`은 계속 독립된 깊은 복사본을 반환한다. 저장과 네트워크 상태 복사 방식은 유지하며 내부의 수정 가능한 배열을 외부에 공개하지 않는다. 전투 판정·패턴 시간·피해량·UI 디자인·씬과 프리팹 자산은 이번 작업에서 수정하지 않았다.

## 메모리 검사

실제 팔라딘 정의를 사용한 .NET 독립 검사에서 핵심 특성·시전 기술·대상·남은 시간을 1,000회 읽었다. 준비 루프 이후 현재 스레드의 관리 메모리 할당량을 비교했다.

| 조회 방식 | 1,000회 조회의 할당량 |
| --- | ---: |
| 전체 Snapshot 복사 후 값 조회 | 2,592,000바이트 |
| 읽기 전용 값 조회 | 0바이트 |

이 수치는 해당 조회 경로의 관리 메모리 검사 결과다. 게임 전체 메모리 사용량, 초당 절감량, FPS 향상률을 뜻하지 않는다.

## 실제 플레이 확인

사용자가 메인 씬 `Assets/Scenes/SampleScene.unity`에서 컴파일 후 확인한다.

1. 직업 선택창에서 설정 버튼을 열고 닫아 버튼과 창이 정상적으로 위에 표시되는지 확인한다.
2. 팔라딘의 기원과 핵심 특성을 바꾼 뒤 표시와 효과가 바뀌는지 확인한다.
3. 실반 오라클·나이트블레이드·스피릿 레인저의 기본 공격과 시전을 확인한다. 이동·취소·사망·재도전 뒤 공격이나 시전이 남지 않아야 한다.
4. 적 생성·사망·스테이지 전환 때 적 목록의 항목과 클릭 대상이 갱신되는지 확인한다.

실제 4인 연결, GC 프레임 멈춤, CPU·GPU 프레임 시간, 메모리 사용량, 드로콜은 별도 측정이 필요하다. Unity·Steam·게임은 이 작업에서 실행하거나 조작하지 않았다.

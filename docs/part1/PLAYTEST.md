# 원본 Unity / Windows 확인 절차

## 빌드 전제

- 최신 변경을 검토하여 **원본** `C:/coopraid/coopraid3d`에 반영해야 한다. 현재 원본은 이전 팔라딘 브랜치와 사용자 변경을 유지하고 있다. 이번 작업은 자동 병합/소스 복사/브랜치 전환을 하지 않는다.
- worktree에서 Unity를 열거나 Library를 만들지 않는다.
- Unity 6000.3.26f1 및 Windows Build Support. 원본에서 컴파일을 마치고 열린 씬의 사용자 변경을 저장한다.
- 원본 메뉴 `Raid Rogue > Build Part 1 Playable (Windows)` 실행. 기존 SceneAutoBuilder로 전용 `Assets/Scenes/Part1_Playable.unity`를 구성하고 이 씬만 빌드한다. 참조 누락/중복 플레이어/잘못된 챕터를 사전 거절한다. 기존 테스트 씬은 다시 쓰지 않는다.
- 출력: 원본 `Builds/Part1Windows/RaidPart1.exe`, `BUILD_INFO.txt`. Builds는 Git 제외. 생성 씬과 meta는 원본 Unity가 관리하며 직접 YAML/GUID를 작성하지 않는다.
- 배치 빌드는 원본 에디터 종료 후:

```powershell
& C:/coopraid/coopraid3d-playable/Tests/Build-Part1Windows.ps1 -OriginalProject C:/coopraid/coopraid3d -CheckOnly
& C:/coopraid/coopraid3d-playable/Tests/Build-Part1Windows.ps1 -OriginalProject C:/coopraid/coopraid3d
```

사전 검사는 원본과 작업 소스를 비교하고, 다르거나 원본 에디터가 열려 있으면 Unity를 실행하지 않는다. CRLF/LF·UTF-8 BOM 차이는 허용하되 실제 텍스트 차이와 추가 컴파일 입력은 검토를 요구한다. 파일을 복사하거나 수정하지 않는다. 빌드 성공은 플레이 성공을 뜻하지 않는다.

사전 검사 자체의 회귀 검사는 `Tests/Run-Part1BuildChecks.ps1`로 실행한다. 실제 임시 파일만 사용하며 Unity/Library를 실행·생성하지 않는다.

### 원본 반영 전 검토 지점

2026-10-24 재개 시 실제 차이: 원본에 없는 파일 24개, 내용이 다른 파일 53개. 다음 5개는 원본 미커밋 수정과 겹치므로 전체 덮어쓰기로 처리하지 않는다.

| 파일 (Assets/Scripts 아래) | 검토할 내용 |
|---|---|
| AegisRouteSelectionUI.cs | 원본의 R/F/V 미구현 안내와 최신 확장 선택 흐름을 대조 |
| CharacterActor.cs | 원본 시험용 API를 유지하면서 최신 12직업/개발 시험 기록 제외 처리 반영 |
| CharacterFrameworkUI.cs | 원본 직업 설명 수정과 최신 12직업 UI/공통 데이터 연결 대조 |
| CharacterRuntimeState.cs | 원본 시험 상태 조작과 최신 선택·보상 상태 처리 대조 |
| RoleSelectionManager.cs | 원본 선택 UI 변경과 최신 12직업/저장된 빌드 고정 정책 대조 |

원본의 ProjectSettings, Tests/AegisRouteTests.cs, 미추적 .meta 및 Editor/CharacterSkillTestWindow.cs도 보존한다. 최신 브랜치에는 시험 창과 관련 API가 이미 있으므로 원본 미추적 파일을 중복 추가하거나 GUID를 다시 만들지 않는다. 이 작업에서는 원본 통합/복사/브랜치 전환을 수행하지 않았다. 반영 후 원본 Unity 컴파일을 먼저 확인하고, 에디터 메뉴 빌드 또는 원본 에디터 종료 후 배치 빌드를 선택한다.

현재 Steam App ID는 0이다. 오프라인/AI/LAN은 사용 가능하다. Steam 테스트는 기존 Configuration 메뉴에서 실제 앱 설정 또는 명시적인 개발 환경 설정을 사용한다. 임의 ID 설정·배포는 하지 않는다.

## 최소 완주 및 회귀 확인

각 결과에는 빌드 시각, 실행 모드, 계정 수, 직업/루트, 시작 체크포인트, 성공/실패와 로그를 기록한다. 개발 강제 처치는 정규 완료/저장 확인에 사용할 수 없다.

1. **싱글 + AI**: 새 게임 → 12직업 중 하나 및 기원 → 출발. Stage 1/6, HP·보호막·자원·보스 HP/캐스팅, 파티 1탱/1힐/2딜 확인. WASD/좌클릭/우클릭/X/Q/E와 변경한 바인딩을 확인한다.
2. **실패 안내**: 타겟 없음/범위 밖/자원 부족/쿨타임/잠금 스킬 입력. 동일 실패가 단일 안내 영역에 표시되고 텍스트가 누적되지 않아야 한다. UI 클릭이 공격·타겟 변경을 유발하지 않아야 한다.
3. **사망/관전**: 보스 타겟을 유지한 채 사망. 이동·공격·대쉬 차단, 이리스 바인딩과 공유 횟수 표시. 이전/다음 파티원 버튼은 카메라만 바꾸며 전투 타겟/조작 대상은 유지. 구조 요청 후 내 카메라 복귀, HP 40%, 기존 보호, 쿨타임 유지. 코인 0이면 이유 표시.
4. **전멸/재도전**: 실패 기록 확인 후 재도전. 공유 부활 4/4, 같은 빌드/카드 유지, 이전 쫄·장판·투사체·예약 피해 없음. 메뉴 복귀 취소/확정 모두 입력 차단을 남기지 않아야 한다.
5. **Stage 1~5**: 처치 후 기존 진화 카드와 R/F/V 선택을 각각 1/2/3에서 완료. 선택 전 다음 전투 금지, 선택 후 다음 경계 저장 및 카운트다운. 각 경계에서 종료/이어하기로 Stage 2~6의 빌드·카드·자원 복구. 전투 중 종료는 마지막 경계로 돌아가며 부활 4회.
6. **Stage 6**: 처치 직후 완료 저장, 결과 1회. Stage 7/다음 전투 카드창 없음. 완료 파일은 진행 중 이어하기로 표시하지 않음. Stage 4~6은 1~3 기존 보스 구성 재사용이며 고유 콘텐츠 검증이 아니다.
7. **LAN 호스트+클라이언트**: 같은 빌드로 localhost 또는 두 PC 접속, 역할/기원/준비/로딩 후 한 스테이지 진행. 중복 카드 요청, 마지막 코인 동시 요청, 보상/전환 중 접속 종료 확인. LAN은 개인 영구 기록 저장 대상이 아니다.
8. **실제 Steam**: 같은 호스트의 새 로비에서 파일 이어하기, 원래 인증 사용자 슬롯/고정 빌드/빈자리 AI. 진행 중 연결 단절 → AI → 복귀 시 HP·남은 부활·포션·쿨타임 유지. 파일 이어하기의 새 도전과 구분. 다른 사용자 인계 거절. 4명 서로 다른 계정으로 최종 확인 필요.
9. **종료 경계**: 보상 도중/전환 도중/최종 처치 직후 종료. 재전송으로 선택이나 완료 기록을 중복 지급하지 않는지 확인. 초대/접속 취소 직후 새 게임에 이전 콜백이 개입하지 않아야 한다.
10. **반복/장시간**: 새 게임→전멸/재도전→메뉴→훈련장→메뉴→이어하기 10회. Hierarchy와 Profiler에서 누적 개체/코루틴/UI·재료·GC·네트워크 전송을 비교. 테스트 전후 실제 측정값을 기록한다. 설정과 키 배치는 유지, 훈련장은 정규 기록 제외.

# Stage 6 노멀 — 시계탑 정문 / 야누스 알파 & 오메가

## 범위와 확정 기획

- Stage 6 전용 노멀 전투. 두 문지기, HP 60% 네 말뚝 동시 당기기, 서로 다른 두 명의 정면 카운터, 1부 최종 정산이 핵심이다. Stage 2 플로라 기어와 별도다. 하드·극한·변신·2부 공간은 추가하지 않았다.
- 지름 40m 반원형 전장(월드 `z <= 0`, 반경 20m). 북쪽 경계는 막혀 있으며 추락·붕괴가 없다. 알파는 탱커 어그로·평타를 맡고, 오메가는 예고 패턴만 사용한다. 일반 패턴과 두 큰 기믹은 같은 상태 기계에서 순차 처리한다.
- HP·일반 공격 6개·공용 HP·말뚝 실패 피해와 세부 시간은 **신규 초기 구현안**이다. `BossController.janus`의 `JanusNormalSettings`에서 조정한다. 사용자가 확정한 리소스가 없으면 임시 모델·기하로 표시한다.

## 초기 조정값

| 설정 | 초기값 |
|---|---:|

| 일반 시전 / 기본 간격 / 회복 | 3.4 / 3.5 / 2.5초 |
| 알파 방패 강타 / 반면 | 520 / 340 |
| 오메가 직선 / 원형 | 360 / 340 |
| 낙인 / 분담 총량 | 320 / 1,100 |
| 말뚝 시작 | 공용 HP 60% 이하, 도전당 한 번 |
| 말뚝 제한 / 네 명 겹침 / 범위 | 22초 / 2초 / 2.1m |
| 말뚝 실패 / 이후 회복 | 파티 피해 850 / 5초 |
| 더블 카운터 준비 / 가능 창 | 4 / 2.2초 |

| 더블 카운터 재등장 최소 간격 | 12초 + 준비 4초 |

알파 기본 위치 `(-5,1,-4)`, 오메가 `(5,1,-4)`이다. 네 말뚝은 `(-12,0,-8)`, `(-5,0,-15)`, `(5,0,-15)`, `(12,0,-8)`이다. 설정의 `postPositions`를 교체할 때 반원 안의 접근 경로와 22초 이동 시간을 확인한다. 일반 카운터는 이 보스의 쌍동 기믹에서만 **푸른색·교차검·전 직업 가능**으로 안내하며, 다른 보스의 금색 일반 카운터와 파란 방패 힘겨루기는 바꾸지 않는다.

## 판정과 AI

- 알파는 기존 `BossController`, 오메가는 기존 `BossAddMinion`의 `JanusOmega` 타기팅 개체다. 오메가의 직접·지속 HP 피해는 알파의 공용 HP로 전달하고, AI 관전 공격 배율은 공용 HP에서 한 번 적용한다. 같은 프레임·시전자·공격 출처의 범위 적중은 양쪽의 순번을 짝지어 한 번만 반영한다. 독립적인 추가 적중·후속 틱은 별도 순번으로 반영한다. 처치·전멸·재도전에는 두 개체와 예고를 정리한다.
- 말뚝은 기존 `Interact` 설정 키로 한 번 상호작용한 뒤 범위 안에 머무는 동안 계속 당긴다. 호스트는 말뚝마다 한 명만 등록한다. 네 명의 유효한 유지가 2초 겹쳐야 성공한다. 사망·이탈 시 해당 등록을 해제하며 인원 부족·시간 초과는 성공으로 위장하지 않는다. AI는 서로 다른 말뚝으로 **실제 이동**해 범위 안에서 유지한다. 관전자는 참가하지 않는다.
- 더블 카운터는 기존 카운터 기술과 정면·사거리·쿨타임 검사로 알파·오메가가 각각 성공한다. 같은 캐릭터는 두 성공을 모두 차지할 수 없다. 먼저 성공한 쪽만 멈추며 실패한 쪽의 직선은 회피할 수 있다. AI는 두 대상의 정면으로 이동하고 준비된 기술을 사용한다. 숨겨진 쿨타임 초기화는 없다.
- 10% 복선은 이야기 대사 두 줄이며 HP를 잠그지 않는다. 공용 HP 0이면 기존 Stage 6 최종 정산이 우선한다. 기존 최종 결과·완료 영수증·중앙 포탈·대기실 복귀를 사용하며 Stage 7을 열지 않는다. 확정되지 않은 정문 너머와 이리스 엔딩 내용은 연결하지 않았다.

## 에디터 리소스 연결

- `BossController.janus`: `alphaVisualPrefab`, `omegaVisualPrefab`, `postVisualPrefab`, `chainVisualPrefab`(말뚝 진행 중 임시 사슬), 음향, 일반 공격 Animator 트리거, 위치·반경·피해·시간. 오메가 임시 개체는 타기팅과 공용 HP를 갖는다. 모델 콜라이더는 별도 피격·이동 규칙과 충돌하지 않게 비활성화한다.
- `RaidLobbyLayout.stage6GateFieldPrefab`, `stage6SealChainsPrefab`, `stage6WeldedBarPrefab`: 전장·정문 사슬·조사 오브젝트 대체. 사슬은 말뚝 성공 시 시각적으로 꺼진다. `bossArrivals`/`bossDefeats`의 Stage 6 엔트리에 사용자 Timeline·카메라·애니메이션을 연결한다. 컷씬 트랙은 기존 `BossAnimator`/`BossTransform`으로 알파를, 새 `JanusOmegaAnimator`/`JanusOmegaTransform`으로 오메가를 연결한다. 오메가 Animator 트랙은 교체 모델에 Animator가 있어야 한다. 누락 시 기존 컷씬 시간과 임시 연출을 사용한다. 제작 자산을 생성 코드가 덮어쓰지 않는다.
- 조사 독백 성향 데이터가 아직 연결되지 않았다면 `RaidApproachField.janusDevelopmentVoice`에서 개발용 한 가지만 지정한다. 성향 성장 시스템은 추가하지 않았다.

## 명령 검사와 사용자 확인

- `Tests/Run-JanusNormalChecks.ps1`: 반원·말뚝 한 명씩 배정·네 명 겹침·사망/이탈·두 명 카운터·범위 피해 짝 판정. `Tests/Run-CombatMetricsChecks.ps1 -OriginalProject C:\coopraid\coopraid3d`: 전체 관리 C# 컴파일과 전투 지표·관전 피해 규칙. `Tests/Run-CampaignSaveChecks.ps1`: 최종 완료·영수증·테스트 저장 기존 규칙. 결과는 HANDOFF에 기록한다.
- 개발 테스트 저장에서 플레이어 1명+AI 3명: 진입로 선택 조사 → 등장 컷씬 정상·건너뛰기 → 알파/오메가 여섯 일반 패턴 개별 회피 → 60% 네 말뚝(사용자 말뚝을 바꿔 AI 재배정, 성공·시간 초과·사망) → 더블 카운터 2/2·1/2·0/2와 두 직선 회피 → 10% 대사 → 처치·결과·포탈·대기실·완료 이어하기를 확인한다.
- AI 4인 관전: Stage 6 **노멀**, 100% 피해 배율로 시작해 네 AI만 말뚝을 차지하고 각자 정면 카운터를 시도하는지 확인한다. 배율 변경은 HP 피해만 바꾸고 말뚝·카운터는 그대로여야 한다. 전멸·재도전과 전체 완주도 확인한다.
- Unity 에디터 임포트, 실제 이동·카메라·입력·AI 성공률·컷씬·4인 Steam·실제 저장 복구는 사용자 Play 전까지 **미검증**이다.

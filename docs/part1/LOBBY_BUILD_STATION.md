# 대기실 별자리 조율대

대기실의 별자리 조율대에서 현재 직업의 루트와 빌드를 설정한다. 기본 위치는 월드 좌표 `(-6, 0, 12)`로, 12시 북쪽 출입구의 왼쪽 옆이다. 기본 출발 문과 조율대의 상호작용 범위가 겹치지 않도록 배치했다.

## 사용 방법

| 순서 | 조작 | 결과 |
| --- | --- | --- |
| 1 | 직업을 선택하고 대기실에서 조율대로 이동 | 원통형 받침·별빛 구체·이름 표식이 보임 |
| 2 | 3m 안으로 접근 | 현재 바인딩의 상호작용 키와 루트 및 특성 설정 안내 표시 |
| 3 | 상호작용 키 입력 | 교체 스킬·핵심 특성·보조 특성 설정창 열림. 기본 키는 G이며 재지정한 키를 따름 |
| 4 | 설정 항목 클릭 | 기존 빌드 선택 규칙에 따라 장착 가능한 후보를 순환 |
| 5 | 루트 변경 버튼 클릭 | 현재 직업을 유지한 채 기원 루트 선택창 열림 |
| 6 | 루트 선택 후 확인 또는 돌아가기 | 루트 선택창이 닫히고 조율대 빌드 설정으로 복귀 |
| 7 | 닫기 버튼 또는 조율대에서 멀어지기 | 설정창 닫힘. 전투 출발·세션 종료 때도 닫힘 |

직업을 아직 고르지 않은 기존 테스트 캐릭터는 직업·기원 선택으로 안내한다. 빌드 설정창은 조율대와 상호작용했을 때 표시하며, 전투 HUD에 항상 펼쳐 두지 않는다.

## 파티 전투 준비 화면

왼쪽 위부터 초상화 없이 4인 파티의 직업 아이콘·직업명·유저명·준비 상태를 표시한다. 가운데는 자신의 교체 스킬·핵심 및 보조 특성을 아이콘 카드로 선택하며, 오른쪽은 실제 현재 스테이지 번호·보스명·세션 난이도를 표시한다. 화면 크기에 맞춰 전체 창의 크기를 조절하며, 창이 열린 동안 0.25초 간격으로 현재 구성을 갱신한다.

파티원 행 아래에는 루트와 대표 스킬 아이콘을 표시한다. 카운터가 실제 장착되어 있으면 금색 배경과 `C✓` 배지를 표시한다. 아이콘의 이름·설명·잠금 정보를 마우스 툴팁에서 확인하며, 선택 카드를 클릭하면 기존 방식으로 다음 장착 가능 후보가 즉시 적용된다. 별도 적용 대기 상태는 없다.

아이콘은 `RaidUIPresentation`의 안정된 데이터 ID 연결을 우선 사용하고, 비어 있는 스킬은 기존 `AstellaOrnateHUD`의 슬롯별 아이콘을 재사용한다. 자산이 없는 직업·특성은 역할 기호 또는 임시 기호를 표시한다. 따라서 모든 기술과 직업의 고유 아이콘 아트가 완성된 상태는 아니며, 이후 Presentation 자산에 연결하면 해당 아이콘을 사용한다. 기존 디자이너 프리팹·아트는 수정하지 않는다.

| 파티원별 정보 | 표시 기준 |
| --- | --- |
| 이름과 나 표시 | 실제 네트워크 이름과 로컬 플레이어 여부 |
| 직업과 역할 | 현재 직업 정의의 탱커·힐러·딜러 구분 |
| 기원 루트 | 현재 선택한 루트 이름, 미선택이면 미선택 표시 |
| 대표 스킬 | 2번 콤보·3번 보조·R 핵심·F 전술의 실제 장착 기술명 |
| 역할 기술과 카운터 | 선택한 역할 기술명과 카운터 장착·미장착·잠김 표시 |
| 준비 상태 | 네트워크 파티원의 로딩·준비·AI 대체 상태 |

카운터 여부는 슬롯 이름이 아닌 기술 정의의 `isCounter` 능력 표식을 사용한다. 딜러가 같은 역할 슬롯에 무력화나 보호 기술을 선택하면 카운터 미장착으로 표시한다. 재사용 대기 중이어도 장착 표시는 유지하며, 잠긴 카운터는 장착 인원에 포함하지 않는다. 하단에는 카운터 장착 인원과 실제 연결 플레이어의 준비 인원을 표시한다.

네트워크에서는 각 캐릭터에 복원된 호스트 빌드를 읽는다. 다른 사람의 빌드를 바꾸거나 주 담당·보조 담당을 자동 배정하지 않는다. 일반 AI 역할 동료는 개별 직업·기원 빌드가 없는 것으로 구분하고, 개인 빌드가 있는 연결 끊김 대체 AI와 구별한다. 빈자리와 아직 동기화되지 않은 정보도 별도 표시한다.

| 항목 | 적용 규칙 |
| --- | --- |
| 루트 | 첫 출발 전의 기존 선택 권한을 따름. 저장 이어하기·진행 중 고정된 루트는 변경 불가 |
| 교체 스킬과 특성 | 기존 대기실 빌드 변경 규칙을 따름 |

| 멀티플레이 | 자신의 선택을 기존 요청으로 호스트에 전달하고 호스트가 검증 |
| 접근 | 대기실에서 조율대 근처에 있고, 메뉴·세션 종료·로딩에 가려지지 않은 상태 |

## 모델과 배치

`Assets/Resources/UI/RaidLobbyLayout.asset`의 `buildStationPosition`, `buildStationRange`, `buildStationPrefab`에서 배치·거리·대체 모델을 설정할 수 있다. 프리팹을 지정하면 코드로 만든 임시 모델 대신 사용한다. 기본 모델은 대기실 생성 시 한 번 만들고 대기실 표시·숨김에 따라 함께 전환한다. 최초 기본값 `(-7, 0, -5)`가 남아 있으면 실제 사용 위치를 북쪽 문 옆으로 이전하며, 별도로 지정한 다른 배치는 보존한다.

씬과 프리팹 YAML은 직접 수정하지 않는다. 기존 UI 디자인을 바탕으로 Unity의 PrefabUtility를 통해 분리하며, 생성 전에 원본 HUD와 메타 파일을 백업한다.

## UI별 프리팹 편집

원본 Unity에서 조율대 프리팹과 기존 슬롯의 빈 루트 정리는 안전한 편집 상태에서 초기화한다. 전체 전투 HUD의 중첩 분리는 메뉴 `Tools > Astella > UI > Separate Editable UI Prefabs`로 명시적으로 실행한다. 기존 씬에서 참조하는 객체 ID가 바뀌는 환경에서는 원본을 복원하고 중단하며, 컴파일 때마다 해당 큰 작업을 재시도하지 않는다.

| 편집 대상 | 생성 위치 |
| --- | --- |
| 조율대 전체 창 | `Assets/Resources/UI/ConstellationBuild.prefab` |
| 조율대 파티 목록 | `Assets/UI/Separated/Station-날짜/PartyRoster.prefab` |
| 조율대 내 빌드 | `Assets/UI/Separated/Station-날짜/MyBuild.prefab` |
| 조율대 스테이지 정보 | `Assets/UI/Separated/Station-날짜/StageInfo.prefab` |
| 전투 HUD·파티·대상·미니맵·메뉴·설정·보상 등 | `Assets/UI/Separated/HUD-날짜/번호-기존이름.prefab` |

전체 HUD는 원래의 GUID를 유지하고 분리된 프리팹을 중첩해서 조립한다. UI 간 참조는 Unity의 native connect로 유지하며, 형제 영역 참조는 조립 부모의 override로 보존한다. 기존 씬·프로필에서 참조하는 HUD 객체 ID가 바뀌면 원본 HUD 파일을 복원하고 오류를 기록한다. 완료 기록은 `Logs/UISeparation-v1.json`, 원본 백업은 `Logs/UIRepairBackups/separation-날짜/`에 둔다. 기존 분리 파일이나 조율대 프리팹을 재생성해서 사용자 수정을 덮어쓰지 않는다.

분리 중 native connect가 컴포넌트를 교체할 수 있으므로 살아 있는 컴포넌트 포인터를 보관해 재사용하지 않는다. 연결 전후 계층 주소로 참조를 복원하고, 계층·컴포넌트 종류가 달라지면 저장을 중단한다. 그림이 있는 실제 단축바 슬롯도 `Dash`, `Potion`, `SharedRevival`, `Skill-슬롯명`으로 분리한다. 기존 `dash` 등 이름의 RaidUIView는 다른 위치의 슬롯을 가리키는 기능 연결용 껍데기일 수 있으므로, 실제 아트는 해당 슬롯 프리팹에서 편집한다.

기존 대시·포션 fallback 프리팹의 빈 전체 화면 루트는, 수정되지 않은 단일 고정 크기 슬롯 구조일 때만 슬롯 크기로 정리한다. 자식 슬롯의 배치를 루트로 옮기고 자식을 루트에 채워 게임 안 좌표를 유지한다. 전체 화면 메뉴나 이미 수정된 사용자 구조는 일괄 축소하지 않는다.

`Tools > Astella > UI > Audit All UI Prefabs`는 현재 프로필 의존성과 이전 보관본까지 검사해 `Logs/UIPrefabAudit.md`를 만든다. 현재 사용 중인 프리팹과 보관·미완료 출력을 구분하며, 스크립트·버튼 바인딩·폰트·종횡비·활성 상태를 기록한다. `UISeparation-v1.json`이 없다면 `HUD-날짜` 폴더가 있어도 전체 분리는 완료된 상태가 아니다. 정적 전체 에셋 연결 검사 결과는 `Logs/UI-All-Prefabs-Static-Audit.json`에 기록했다.

Project 창에서 해당 프리팹을 더블 클릭해 편집한다. 전체 창의 열 배치를 조절할 때는 `ConstellationBuild`, 각 열 안의 디자인을 조절할 때는 해당 중첩 프리팹을 연다. 메뉴처럼 기본적으로 비활성인 프리팹은 미리보기할 때 활성화 상태도 확인한다.

조율대의 `RaidBuildStationView`는 이름·계층 대신 명시적 참조로 버튼과 아이콘을 연결한다. 배치·폰트·색상은 실행 코드가 초기값으로 재설정하지 않는다. 아이콘을 고정 아트로 바꾸려면 해당 Icon 바인딩의 `overrideSprite`를 지정한다. 스킬 선택에 따라 바뀌는 아트는 기존 Presentation의 데이터 ID 연결을 사용한다. `fitToCanvas`를 끄면 창의 자동 축소도 해제된다. 카운터 장착·미장착 색상은 View의 두 색상 필드에서 편집한다.

프리팹 모드의 예시 직업명·유저명·스테이지 텍스트는 편집용 미리보기이며, 실제 플레이에서 현재 상태로 갱신한다. 버튼 콜백은 실제 생성 시 한 번 연결하며, 에디터 생성에 플레이 세션이나 네트워크 접속은 필요하지 않다. 아직 생성되지 않은 환경에서는 코드 기반 기본 창으로 동작한다.

## 확인 범위

### 하단 전투 HUD 배치

`AstellaSplitCombatHUD`가 원본 편집기의 안전한 컴파일 후 한 번 적용된다. 수동 메뉴는 `Tools > Astella > UI > Apply Split Combat HUD`다. 완료 기록은 `Logs/SplitCombatHUD-v1.txt`이며 이후 자동으로 디자이너 편집을 초기화하지 않는다. 실제 프리팹 저장은 Unity API로 처리하고 기존 HUD 및 메타는 `Logs/UIRepairBackups/split-combat-날짜/`에 백업한다.

Play 중에는 프리팹 저장을 하지 않는다. 편집 모드로 돌아오면 누락된 프리팹·씬 배치를 확인한다. `ExitingEditMode`에서 `isPlaying` 검사에 걸려 적용이 막혔던 경로는 제거했다. 대신 `AstellaOrnateHUD` 첫 갱신에서 이전 한 줄 HUD를 한 번만 전환한다. 프리팹 authoring과 실행 중 전환은 같은 `AstellaSplitCombatLayout`을 사용한다. 이 경로는 편집기 메뉴가 대기해도 새 게임 HUD에 새 배치가 표시되도록 하는 이행용 처리다.

`combatLayoutVersion = 1`인 프리팹·씬은 런타임이 배치·디자인을 재설정하지 않는다. 아직 버전이 없는 UI도 `Actions`·`Vitality`가 있는 알려진 기존 구조만 전환하며, 필요한 9개 버튼을 먼저 검사한다. 이미 좌우 배치인 UI는 버전만 표시하고 유지한다. 프리팹 파일뿐 아니라 현재 씬의 실제 버튼 부모도 확인해 이전 배치 override를 보완한다. 씬은 수정 상태로 남기며 원본 씬 파일을 별도 백업한다.

| 위치 | 구성 |
| --- | --- |
| 하단 왼쪽 | Gcd1·Gcd2·OffGcd1·Counter: 기본 키 1·2·3·4 |
| 하단 오른쪽 | Job1·OffGcd2·Identity: 기본 키 Q·F·R, 추가 간격 뒤 Space 이동기 |
| 하단 중앙 | 실제 직업 자원 링·문양·수치, 작은 정수 자원은 칸 표시; 그 아래 V 필살기 |
| 왼쪽 스킬 위 | 체력 |
| 오른쪽 스킬 위 | 실제 V 기술에 별도 자원 비용이 있을 때 해당 자원 게이지 |
| 왼쪽 바깥 별도 작은 슬롯 | 포션, 메인 슬롯의 62% 크기 |
| 왼쪽 위 파티 HUD 오른쪽 | 공유 부활 코인·수량·기존 키 표시 |

실제 키 표시는 기존 키 바인딩을 사용하므로 재지정한 키를 따른다. 공격 범위를 벗어나라는 하단 경고 행은 표시하지 않는다. 중앙 아덴에는 기존 아트를 재사용하며, 직업별 `JobVisual.identityEmblem`·`identityColor`와 연결된 UI 프리팹에서 문양·색상·구조를 편집할 수 있다. 팔라딘·오라클·나이트블레이드·레인저의 기본 문양과 색상을 구분한다. 스킬 사용·자원 생성·소모 규칙은 바꾸지 않는다.

### Play에서 직접 조정한 배치 보존

2026-11-06 사용자가 Play에서 조정한 레이아웃은 `AstellaPlayHUDLayout`이 `Logs/UserHUDLayout-20261106.json`으로 캡처한다. 대상은 플레이어 HUD 루트·좌우 그룹·중앙 게이지·V·포션·나머지 슬롯·키 배지·체력/자원 영역·공유 부활의 RectTransform 위치·앵커·크기·피벗·스케일·회전이다. 체력·쿨다운·활성/준비 상태·문자열 등 게임 진행 상태를 저장하지 않는다. 버튼과 스크립트는 기존 연결을 사용한다.

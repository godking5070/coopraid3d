# 힐러 3직업 9키 9루트 통합 설계

기준은 사용자가 2026-11-02 제공한 상세 힐러 명세다. [원문 사본](HEALER_ORCA_SOURCE_20261102.txt)에 자원·대상·입력·스킬·특성 전문을 보존했다. 원래 OneDrive 파일은 수정하지 않았고 사본의 파일 해시 일치를 확인했다. 이 문서는 원문의 비교표·운영 예·구조 검토이며, 생략된 세부 규칙은 원문을 따른다. 새 설계의 런타임 구현과 수치 시뮬레이션·플레이 검증은 하지 않았다.

## 확정 조건과 제안의 구분

- 사용자 확정 조건: 1부 탱1/힐1/딜2의 4인, 2부 탱2/힐2/딜4의 8인, 보스→대기실→다음 보스, 직접 스킬·특성 선택, 직업별 3루트, 9개 스킬 키와 키 내부 콤보, 공중 상태 없음, 동료 시너지, 파티 카운터 분담과 카운터/무력화 구분. 딜러 선택 카운터 방향 유지.
- 아래 힐러 키 역할, Q 2충전, 자원 수급, 9루트·특성·시전자별 보호막 정책과 모든 숫자는 **현재 설계 제안**이다. 상세하더라도 사용자 확정 또는 검증된 밸런스로 승격하지 않는다.
- 계수·쿨타임·거리·시작 자원·부활·스토리 해금·효과 상한과 아래 예외는 미정이다. 기존 F 해금을 자동 복제하지 않으며 필수 회복/정화가 필요한 콘텐츠 전에 기본 기능을 확보하는 방향이다. 부활을 특정 직업/V/숨은 키에 임의 추가하지 않는다.
- 식별자는 힐러 O1~O3(오라클), B1~B3(바드), A1~A3(약사)다. 탱커 문서의 A/B/C와 충돌하므로 코드·저장 ID를 정할 때 역할/직업 이름을 함께 포함해야 한다. 현재 표기만으로 기존 루트 ID를 재사용하지 않는다.

## 공통 입력 자원 대상 제안

- 1·2 공유 GCD는 초기 2초. 진행은 독립, 2 대상 변경으로 콤보 초기화 없음. 모든 2 선택지는 각 입력부터 직접 회복한다.
- 1 완주는 유효 마지막 적중, 2 완주는 살아 있는 유효 지원 대상의 마지막 직접 치유 시전으로 동등한 자원을 1회 얻는다. 과치유도 인정하며 적 수/타수/치유 대상 수에 곱하지 않는다.
- 2는 직업 자원 무소비. 보스 공격 불가 시 유효한 2를 사용하며 허공 공격으로 공격 자원을 얻지 않는다. HoT/자동 회복/추가타/보호막은 자원·성장을 재귀 생성하지 않는다.
- 공격 대상과 지원 대상은 별도로 유지한다. 지원 대상 미지정은 자신, 명시 지정 후 무효는 안내/불발이다. 이 차단은 2/Q/단일 지원 3/R에 적용하며 F·자신 중심 광역 R/V·공격에는 전파하지 않는다. 파티 UI를 사용한다.
- Q는 2충전·순차 재충전 초기안. 직접 긴급 회복과 정화 가능한 효과 1개 제거를 같은 충전으로 처리한다. 보스 대상/강제 교대 표식을 자동 정화하지 않는다. 정화 우선순위는 미정이다.
- Q/F/4/Space는 직업 자원 없이 작동한다. F는 쿨타임이 있는 직접 광역 회복, Space는 지상 이동/기본 무적 없음. V는 별도 게이지이며 직업 자원/Q를 자동 초기화하지 않는다.
- 스테이지 진입/재도전 시 정해질 시작 자원으로 초기화하고 대기실 반복 시전은 자원을 생성하지 않는 초기안이다. 콤보·V·Q 충전·예약·루트 상태의 구체 리셋 정책을 추가로 결정해야 한다.
- R 채널 중 Q/F/4/Space는 즉시 실행한다. 필요한 채널 취소 후 입력을 버리지 않으며 취소 악절/공격 자동 완주 없음.

## 보호막과 회복 출처 최신 제안

이 절은 앞선 [탱커 명세](TANK_REDESIGN.md)의 동명 보호막 정책을 보완하는 최신 제안이다.

- 같은 시전자·같은 효과는 중첩하지 않고 기존 남은 양과 새 양 중 큰 값을 유지한다. 서로 다른 시전자의 보호량은 출처별로 보관한다. 이는 무제한 합산 허용을 뜻하지 않는다. 합산 상한·수명 갱신·소모 우선순위는 공통 정책으로 정한다.
- 잔량 전환은 자기 출처만 사용한다. 다른 보호막이 전부 흡수하면 자기 소모 효과를 발동하지 않는다. 수호 악절은 같은 시전자 재적용 자체를 금지하는 예외다.
- 같은 시전자·같은 HoT는 무제한 중첩 금지, 다른 시전자의 HoT는 독립 유지. 피해 감소의 출처/중첩 정책까지 자동 변경한 것으로 해석하지 않는다.
- 공격 치유는 직접 행동 1회당 고정 계수다. 실제 피해·취약 배율·치명타·타수·저체력·유효 회복량이 자원/공격 보상을 증폭시키지 않는다.
- 4인/8인의 광역 지원 대상 수, 동일 직업 2힐의 출처, 협공 총 예산을 따로 검토한다. 기본 사거리와 F 범위는 위험 집합/필수 특성 없이 단독 힐이 가능한 수준을 목표로 하되 수치는 미정이다.

## 9루트의 자원과 R 상태

오라클 꽃봉오리와 바드 공명음은 최대 3, 1·2 완주 각각 +1. 약사 영약은 0~100, 완주 각각 +20. 약사 A2만 영약을 배합 3칸으로 교체하며 이중 자원 요구 없음. 아래 시간/상한/비율은 모두 초기안이다.

| 루트 | R 상태와 자원 | 회복을 완성하는 판단과 시너지 |

## 전투 규모와 공격 불가 구간의 운영 예

다음은 입력·자원 경로 예이며 회복량이나 생존 가능성을 검증한 결과가 아니다. 시작 자원을 0으로 정한 것도 아니다. 필요한 자원은 앞선 유효 완주로 확보했다고 가정한다.

| 루트 | 4인 단독 힐 예 | 8인 2힐 및 공격 불가 구간 예 |
|---|---|---|
| O1 | 묘목을 탱커와 다음 대상자에게 배치,2로 위험 대상 성장/Q 급한 회복/F 광역 | 같은 오라클이어도 자기 묘목만 촉진, 다른 힐러와 개화 시점 분담. 적 없이2 완주로 봉오리 |
| O2 | 산개 지점 두 꽃, 유효2 완주로 중계하며 Q/F 유지 | 꽃 겹침은 시전자별 완주당 동료1회. 다른 오라클 파동/출처와 혼동 금지, 적 없이2로 중계 |
| O3 | 저장→2 입력으로 성장→위험 시 수확, 준비 중 Q/F 사용 | 다른 힐러가 선행 피해 복구, 수확은 후속 큰 피해에 배정. 적 없어도 수확 회복 |

## 적용 순서 제안과 상태

1. 역할별9키 입력/독립 공격·지원 대상/2의 각 단계 직접 회복/자원 동등 수급을 공통 기반으로 설계한다.
2. 직접 입력 이벤트와 결과 회복을 분리하고 출처·스킬 인스턴스·전투 세대로 중복/재귀를 막는 규칙을 정의한다. 탱커 표식과도 같은 사건 분류를 사용하되 발동 허용 정책은 효과별로 둔다.
3. Q 충전·정화 필터/순차 재충전, 채널 취소 우선, 시전자별 보호막·HoT/층 소모·정산을 만든다. 자원·출처 UI와 네트워크/저장 이전도 함께 설계한다.
4. 9루트의 상태 및 2·3/핵심 1/보조 2 선택 UI를 순차 연결한다. 기존 자원/패널티/보상과 새 효과를 중복 적용하지 않는다.
5. 명령 검사와 나중 통합 플레이를 분리한다. 4인 단독, 8인 동일 직업 2힐/다른 직업 2힐, 보스 공격 불가, 정화+회복 동시 수요, 채널 취소·지연을 후속 검증 목록에 둔다.

현재 상태: 원문 보존과 문서/코드 대조 구조 검토. 런타임 미전환, 새 빌드 없음, 회복량·보호량·성능·밸런스 미검증. ORCA로 외부 전송하지 않았다.

후속 기반: `CombatActionRules.cs`에 직접 입력 출처·유효 콤보·과치유 적격성과 전투별 중복 권한 방지를 구현했다. 독립 모듈의 명령 검사는 통과했지만 힐러 실행부 연결은 아직 없다. 따라서 위 런타임 미전환 및 밸런스 미검증 상태는 유지한다.

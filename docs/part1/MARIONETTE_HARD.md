# Stage 4 하드 · 버려진 오페라 극장 : 기억의 인형사, 마리오네트

## 범위

Stage 4 노멀의 보스, 실 타기팅, 조종, 무력화, 인형극, 보상 및 저장 흐름을 확장한다. 노멀 값은 `BossController.marionette`에 그대로 남고 하드 값은 `BossController.marionetteHard`에 따로 있다. 극한은 이 구현의 분기에 들어가지 않는다. 기존 1탱·1힐·2딜과 R/F/V를 사용하되 특정 직업이나 V 타입을 요구하지 않는다.

확정 기획은 일반 공격 후속 동작, 기억의 재연, 황금 실의 횡단, 두 실 구출과 반동, HP 40% 변신, HP 30% 구출→재집결→12초 클라이맥스, AI 대응이다. 아래 수치와 재연 인형 후보 위치, 변신 외형은 조정 가능한 초기 구현안이다. 노멀의 한 가닥 실과 HP 30% 직행 클라이맥스는 유지한다.

## 상태와 판정

하드는 기본 공격 6종과 구출, 횡단을 가중치 후보로 사용한다. 횡단을 먼저 단독 소개하고 같은 공격의 연속 선택을 피한다. 반쪽의 막·비극의 중심은 첫 타격 당시 방향을 기록해, 후속 공격 뒤 전투용 인형에서 한 건씩 재연한다. 재연 원점은 인형의 유효한 무대 내 위치이며 기록 방향은 바뀌지 않는다. 추적 조명 뒤 잔류 위험은 다음 핵심 패턴 전에 끝난다. 황금 실의 횡단은 I/II 경로를 순서대로 예고하고 각 통과의 피해를 대상당 한 번만 준다.

하드 구출은 기존 `BossAddMinion` 실 두 개를 별도 HP로 생성한다. 두 개가 모두 파괴되어야 조종을 해제한다. 대상은 초당 0.6m로 보스 쪽으로 끌려가며 무대 경계 안에 묶인다. 구출 성공 후 대상 주변 반동을 2.5초 예고한다. 실패·사망·접속 해제·처치·전멸·장면 이동에서는 실과 조종을 정리한다. 대상 본체를 공격해 구출하거나 대상의 스킬·포션을 자동 소비하지 않는다.

HP 40%는 현재 패턴 종료 뒤 한 번만 변신한다. 남은 HP는 유지되고 변신 중 전투 피해·AI 행동·입력이 제한된다. 컷씬 정상 종료, 건너뛰기, 프리팹 부재는 같은 종료 경로에서 입력과 카메라를 복구한다. 기본 도형 연출에는 무대에 닿는 하부가 남고 기존 보스 타기팅/피해 크기를 확대하지 않는다. 이후 HP 30%는 별도 기록으로 예약하며, 구출 두 실→반동 또는 실패 정리→재집결 3.5초→12초 무력화 순서다. 생존자가 1명 이하라 구출이 불가능하면 준비 구출을 취소하고 재집결로 넘어간다. 클라이맥스에는 3초 간격의 예고된 파티 피해가 들어가며, 성공 시 남은 맥동과 인형극을 즉시 중단하고 기존 관리자 방화벽·그로기를 실행한다. 실패 피해와 같은 시각의 맥동은 겹치지 않는다. 보스 처치가 먼저 확정되면 예약 단계는 취소된다.

호스트가 패턴·실·재연·피해·변신·무력화 결과를 확정하고 기존 전투 스냅샷에 하드 시각 상태를 복제한다. 기존 Stage 4 처치 컷씬, 보상 영수증, XI시 관, 일곱 번째 동료 연결, 포탈, 대기실, 이어하기 및 공용 부활 4회 경로를 재사용한다. 별도 영구 보상이나 저장 키는 추가하지 않았다.

## 초기 조정값과 리소스

`Assets/Scripts/MarionetteHardData.cs`의 `MarionetteHardSettings`가 하드 전용 설정이다. `combat`은 기본 피해·반경·일반 시전·패턴 간격을 조정하며 노멀 설정과 다른 인스턴스다. `healthOverride=0`은 노멀의 현재 HP **46,000**을 임시 기준으로 사용한다. 일반 시전 3.5초, 패턴 대기 3.2초, 자동 공격 간격에만 템포 1.2를 한 번 적용한다. 구출·반동·횡단 이동·카운터·회복·그로기·변신·클라이맥스 시간은 이 배율에 넣지 않는다. 전체 시간 배율이나 Animator 속도는 바꾸지 않는다.

| 항목 | 초기값 |
|---|---:|
| 피해 범위의 마지막 강조 / 카운터 가능 시간 | 0.4초 / 1.6초 |
| 탱커 두 번째 타격 / 반면·중심 후속 간격 | 2초 / 2초 |
| 조명 잔류 | 2초, 반경 2.7m, 피해 110 |
| 재연 대기 / 시전 / 피해 | 2.5초 / 2.5초 / 320 |
| 횡단 폭 / 각 통과 / 사이 간격 / 피해 | 2m / 3.5초 / 2초 / 340 |
| 구출 제한 / 실 한 가닥 HP / 끌림 | 15초 / 1,200 / 초당 0.6m |
| 구출 반동 예고 / 반경 / 피해 | 2.5초 / 3m / 240 |
| 변신 조건 / 연출 / 후 회복 | HP 40% / 8초 / 3초 |
| 클라이맥스 조건 / 재집결 / 무력화 | HP 30% / 3.5초 / 기존 12초·요구량 420 |
| 클라이맥스 맥동 | 3초 간격, 피해 150, 1.5초 전 예고 |

`BossController.marionetteHard`의 `transformedVisualPrefab`, `transformedAnimatorController`, `transformationPresentation`, `cutsceneSkipKey`, 효과음 및 후속/재연/횡단 Animator 트리거가 교체 지점이다. 기존 등장·처치 Timeline은 `RaidLobbyLayout.bossArrivals`/`bossDefeats`의 Stage 4 항목, 무대·보조 인형극·방화벽·진입로 소품은 노멀 명세의 설정을 공유한다. 변신 Timeline·전용 모델·애니메이션·이펙트는 아직 사용자 에셋 연결 전이다. 기본 도형과 기존 모델/트리거로 동작하게 했으며 완성 연출로 간주하지 않는다. 자동 생성 코드는 사용자 자산을 덮어쓰지 않는다.

횡단의 안전 목표는 첫 통과 때 x=-6m, 두 번째 통과 때 x=+6m다. 기본 이동 7.8m/s에 현재 직업 최저 속도 배율 0.9를 적용한 7.02m/s에서는 12m 이동에 약 1.71초가 걸린다. 초기 간격 2초 안에 들어가지만 실제 경로 탐색과 입력 지연은 원본 Play에서 확인해야 한다.

## 검사와 직접 확인

`Tests/Run-MarionetteHardChecks.ps1`은 25개 시간·임계치·기하 규칙을 통과했다. 노멀 15개, Flora 하드 12개, Campanella 하드 18개 회귀 검사와 캠페인 저장 31,881개도 통과했다. `Tests/Run-CombatMetricsChecks.ps1 -OriginalProject C:\coopraid\coopraid3d`는 전투 지표 1,042개와 런타임/에디터 관리 코드 컴파일을 통과했다. 네트워크 검사는 기본 3,737개 통과 뒤 기존 `Combat network logic tests failed` 및 `Exception.ToString()` 출력 실패가 재현되어 전체 통과가 아니다. Unity 컴파일/Play, 실의 실제 타기팅과 AI 화력, 느린 캐릭터 이동, 네트워크 재접속, 영상·카메라·오디오, 4인 Steam 플레이는 명령 검사로 확인하지 못했다. 원본 Unity에서 격리 개발 테스트 저장만 사용한다.

1. 플레이어 1명 + AI 3명으로 하드 일반 공격 여섯 개를 확인한다. 2연타·반면 반대쪽·중심→도넛, 조명 잔류, 집합 회복, 금색 카운터의 시전바/동작/피해 순서와 노멀 수치 보존을 본다.
2. 기억의 재연 인형의 종류·방향·원점과 황금 실의 횡단 I→II 안전 공간을 확인한다. 횡단 한 번에 중복 피해가 없어야 한다.
3. 탱커·힐러·딜러를 플레이어로 바꿔 각각 조종 대상과 AI 구조자를 확인한다. 실 두 개를 공격해야 구출되고, 반동 예고 뒤 이탈할 수 있어야 한다.
4. HP 40%에서 변신과 건너뛰기를 각각 확인한다. HP 유지, 근접 타기팅, 카메라·입력 복구를 본다.
5. HP 30%에서 구출→반동→재집결→12초 무력화를 성공·실패로 확인한다. 맥동 회복과 성공 즉시 배경 차단, 실패 후 회복, 중복 피해 방지를 본다.
6. HP 40%와 30%를 빠르게 넘기고 처치·전멸·재도전·이어하기를 확인한다. 예약 순서, 위험물 정리, 보상·동료 해금 중복 방지를 본다.
7. 개발 명령 없이 노멀과 하드를 각각 전체 완주한다. 실제 4인 Steam 검증은 별도로 남긴다.

# Stage 1 · 마을 수호 석상 노멀

기준은 이 문서와 `GuardianNormalSettings`다. `research/cactbot/보스 패턴 설계 기준.md`, `사례별 설계 노트.md`, 최신 석상 기획안은 `C:/coopraid`에서 찾지 못했다. 새 수치는 이번 사용자 요청의 초기 조정값이며, 참고 제안을 확정 설정으로 더하지 않았다.

보스 최대 HP는 **30,000**이고, 50% 기준은 **15,000**이다. 기존에 메모리에 남은 65,000 기본값은 다음 전투 준비 때 한 번 30,000으로 전환한다. HP 잠금, 강제 무적, 광폭 제한시간은 없다. 강한 파티가 여덟 패턴을 모두 보기 전에 처치할 수 있다. 처치 확정이 50% 기믹보다 우선한다. 피해량, 방어력, 보상은 HP 조정과 연동하지 않는다.

`Assets/Scripts/GuardianNormalData.cs`의 `tempo=1.2`는 일반 패턴의 기준 시간만 나눈다. 단계 시작 시 계산한 호스트 시각 하나를 예고, 바닥 도형, 시전바, 임시 무기 자세, 실제 판정에 사용한다. 전역 `Time.timeScale`과 공통 Animator 속도는 전투 구현에서 건드리지 않는다. 다음 표는 기본 설정이며 Inspector에서 Stage 1 데이터만 조정할 수 있다.

| 패턴·단계 | 기준 | 적용 |
|---|---:|---:|
| 침입자 징벌 예고 | 3초 | 2.50초 |
| 돌봉 휩쓸기 예고 | 4초 | 3.33초 |
| 방패 밀쳐내기 예고 | 3.6초 | 3.00초 |
| 석편 낙하 추적 → 고정 | 3초 → 2초 | 2.50초 → 1.67초 |
| 돌봉 직선 파쇄 추적 → 고정 | 2.4초 → 1.2초 | 2.00초 → 1.00초 |
| 광장 내려찍기 예고 | 4초 | 3.33초 |
| 성문 쇄도 준비 | 4초 | 3.33초 |
| 방패 공명 예고 | 6초 | 5.00초 |
| 첫 대기 / 기본 패턴 대기 | 2초 / 5초 | 1.67초 / 4.17초 |
| 큰 피해 뒤 회복 대기 | 별도 초기값 | 5.50초 |
| 카운터 창 / 성공 그로기 | 고정 | 2초 / 6초 |
| 수호핵 과부하 / 성공 그로기 | 고정 | 10초 / 8초 |

첫 소개는 징벌 → 휩쓸기 → **밀쳐내기** → 석편 → **직선 파쇄** → 내려찍기 → 쇄도 → 공명이다. 이후 여덟 패턴 중 적게 등장한 후보를 우선해 고르고 같은 패턴의 즉시 반복과 징벌·공명의 연속을 막는다. 50% 무력화는 진행 중 공격이 종료되면 다음 공격보다 먼저 실행한다. 한 도전에 한 번이고 재도전 때 초기화한다.

방패 밀쳐내기 초기값은 **정면 120도·10m, 피해 420, 3m 넉백**이다. 예고 시작 시 보스 방향과 중심이 고정되며 기존 넉백 이동 처리로 광장 안에 멈춘다. 카운터, 피해 반사, 정면 무적 효과는 없다.

돌봉 직선 파쇄 초기값은 **폭 4m·최대 24m, 피해 480**이다. 생존한 비탱커를 우선 표적으로 고른다. 2초 동안 대상 방향으로 경고선이 움직인다. 표적이 죽으면 새 표적으로 처음부터 다시 예고한다. 고정 순간 표식을 없애고 경고선을 주황색으로 바꾸며 낮은 음향을 낸다. 이후 1초간 방향과 원점을 유지한 뒤 동일한 직사각형으로 한 번 판정한다. 선 길이는 18m 광장 경계에서 잘라 표시와 판정을 일치시킨다.

AI는 기존 이동 속도로 표시된 부채꼴을 벗어나고, 파쇄 대상은 다른 파티원에게서 떨어져 선을 유도한다. 선이 고정되면 대상과 비대상 모두 폭 밖으로 이동한다. 추적 예고 반응 지연 초기값은 0.65초, 위치 고정 신호 반응 지연은 0.2초다. 텔레포트와 쿨타임 초기화는 쓰지 않는다. 가장 느린 기본 이동 예시인 이지스 팔라딘의 7.02m/s에서 직선 폭 4m 밖으로 나가는 데 필요한 약 3.35m는 고정 후 0.8초의 이동 가능 거리 약 5.62m보다 짧다. 이는 기하학상 가능성 계산이며 실제 장애물·입력 지연 검사는 따로 필요하다.

씬·프리팹 YAML과 사용자 Timeline·카메라·UI는 수정하지 않는다. 기존 도입 → 플레이어 진입 → 소환 → 등장 컷씬 → 카운트다운 → 전투 → 처치 컷씬 → 보상 → 포탈 → 대기실/Stage 2 흐름을 사용한다. 개발 검사는 원본 Unity의 `.git/codex-backups/guardian-stage1-20261027/run-guardian-check.json` 요청을 통해 `test-profiles/guardian-*` 저장만 사용한다. 개발 명령의 강제 패턴 결과와 정상 선택 전투 결과를 혼동하지 않는다.
